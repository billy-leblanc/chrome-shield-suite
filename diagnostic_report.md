# Diagnostic Report: Chrome Shield Suite Runtime Errors

## 1. Primary Bug: Illegal ES Module Imports
- **Location**: `extension/content.js` (and potentially `background.js`)
- **Error Type**: `Uncaught SyntaxError: Cannot use import statement outside a module`
- **Description**: The built `content.js` contains a line like `import { ... } from "./assets/client-...js";`. 
- **Impact**: **CRITICAL**. Chrome Extension content scripts (MV3) do not support ES module imports. This prevents the "Shield" from ever loading on PayPal, Venmo, or Zelle.

## 2. Root Cause: Vite Code-Splitting
The current `vite.config.ts` uses standard Rollup input/output settings. Because `payment_interceptor.tsx` (Content) and `index.html` (Popup) both share React dependencies, Vite/Rollup automatically splits these into a shared chunk in `assets/`.

## 3. Recommended Fix for Claude
Update `vite.config.ts` to ensure that content and background scripts are **self-contained bundles**.

### Suggested Configuration Change:
```typescript
// vite.config.ts
export default defineConfig({
  // ... existing aliases
  build: {
    outDir: "extension",
    rollupOptions: {
      input: {
        popup: path.resolve(__dirname, "index.html"),
        content: path.resolve(__dirname, "src/content/payment_interceptor.tsx"),
        background: path.resolve(__dirname, "src/background/risk_engine.ts"),
      },
      output: {
        // Force content and background to be self-contained
        manualChunks: (id) => {
          if (id.includes('src/content') || id.includes('src/background')) {
            return undefined; // Let rollup handle it, but we need to ensure no splitting
          }
        },
      }
    }
  }
});
```
**Preferred Option**: Use `@crxjs/vite-plugin` or `vite-plugin-web-extension` to handle the manifest and bundling automatically.

## 4. Manifest Cleanup
- The manifest references `popup.html` and `index.html`. Ensure `default_popup` points to the correct entry point generated by the build.
